# Cloud saves merge review design

## Goal and boundaries

Prepare `feat/cloud-saves` for review without merging it. Preserve existing saves and unrelated local files. Work in separate commits for the current native-dialog changes, security, title-screen reliability, repository hygiene, and visual consistency. Run `bun run check` after each group. Do not add native browser dialogs or em and en dashes to strings and docs.

## Commit order and interfaces

1. Commit the already-written native-dialog changes, slot-choice tests, project rule and roadmap entry. Include the reviewed local Supabase config and its ignore file so `supabase start` is reproducible. Include this design document in the first commit. Leave generated `next-env.d.ts` and unrelated untracked files alone. The later hygiene commit will replace the duplicated `CLAUDE.md` rules with `@AGENTS.md`.
2. Security: extract a pure callback redirect validator. Reject raw backslashes, control characters and whitespace, plus encoded leading slashes that could disguise a network-path redirect; resolve against a trusted origin; accept only local paths on that origin, otherwise use `/terminal`. With a valid `NEXT_PUBLIC_SITE_URL` set, use its origin instead of forwarded or Host headers; an invalid configured URL fails closed rather than trusting headers. Retain the existing local header behavior when the variable is unset. Map provider and exchange errors to fixed, user-facing messages without reflecting provider text. Add a new `0002_tighten_grants.sql` that revokes anonymous reads from saves and profiles. Keep applied `0001` unchanged. Do not drop the shared `pgcrypto` extension just to remove a redundant historical declaration, because another Supabase object or deployment may use it. Document this deviation and the client-only nature of the seq guard. Test hostile redirects and anonymous permission failures before fixing them.
3. Title: show an inline `role="alert"` message with a retry path on slot-list, resume and history-restore failures. A single busy guard prevents duplicate starts or replacements, including concurrent async calls; test it. Remove or limit the `autostart` query path to development. Comment that the title tape's `Math.random` values are decorative. Update the inaccurate LOAD-UI roadmap claim while keeping the full damaged-save recovery dialog deferred with a trigger.
4. Hygiene: untrack the eight `.aistudio` images without deleting local copies; ignore `.aistudio/` and `.freebuff/`. Rename the package to `tape` in the manifest and lockfile. Remove the unsupported `next clean` script, as the installed Next.js 16.4.2 CLI guide lists no such command. Make `CLAUDE.md` exactly `@AGENTS.md` and link the roadmap from README.
5. Visual consistency: add one hairline `--shadow-float` token and replace only the requested deep shadows. Use the app background token for requested overlays and accent button text, verify text contrast, permit dialog text selection, and simplify only the requested title eyebrow and form-label casing. Leave terminal micro-labels intact.
6. Performance: document the current proxy `getUser()` cost and the precise trigger for narrowing its matcher. Do not change proxy behavior now.

## Verification and failure behavior

The first group keeps the existing dialog keyboard and destructive-action behavior. Later groups add tests for redirect validation, duplicate-start exclusion, and visible load-failure copy; the RLS SQL test must observe an anonymous permission error. Each group passes lint, typecheck, tests and production build before its commit. On the final build, repeat the recorded manual guest trade-reload, 20x long-career save, profile creation, and title magic-link scenarios against local Supabase. The referenced `tape-cloud-verification.md` is not in this repository, so record exactly which scenarios were run and leave any missing coverage open with a before-public-launch trigger. Do not introduce Playwright for a single smoke test. Record decisions, deviations and unverified work in `docs/ROADMAP.md`.
